# Solai project handoff

## Working model

This is a static Astro website. Editable source lives in `src/`, and unchanged public assets live in `public/`. `dist/` is generated, ignored build output; never edit it directly. Keep scoped changes in the existing Astro, CSS and vanilla JavaScript files. Do not introduce client frameworks, server adapters or extra dependencies unless requested. Enter the Node.js/pnpm shell with `nix develop` (or nix-direnv), and use pnpm for dependencies and the development/build/preview commands in `CONTRIBUTING.md`; do not deploy as part of ordinary editing. Keep `pnpm-lock.yaml` as the only dependency lockfile. Git and Jujutsu are colocated; preserve both `.git/` and `.jj/`.

Use Conventional Commit descriptions for named changes, such as `feat: ...`, `fix: ...`, `refactor: ...`, `build: ...` and `chore: ...`. After completing and verifying a change, describe it and run `jj new` before handing back. Always leave `@` as a fresh, empty working change rather than leaving completed work checked out.

Production hosting is intended for Wisp at `https://solai.style/`, using the `solai` site in the account supplied through `WISP_HANDLE`. `.github/workflows/deploy.yml` checks/builds PRs and deploys only `main` pushes or manual `main` runs. `pnpm deploy:wisp` publishes an already-built `dist/` using the pinned CLI in `scripts/deploy-wisp.sh`; it requires `WISP_HANDLE` and the secret `WISPCTL_APP_PASSWORD`. Never invoke it during ordinary verification or expose the password in source, logs or arguments. Domain claiming/DNS are separate one-time setup; see `CONTRIBUTING.md`. Keep the deploy command CI-provider-independent for a future Spindle, and do not configure or publish to a Spindle until one exists.

Styling uses Tailwind CSS v4 and `@tailwindcss/vite`. `Page.astro` imports the single `src/styles/main.css` entry. Keep complete utility strings in Astro and JavaScript DOM builders; do not construct utility names dynamically. Reuse the `solai-*` semantic colour utilities and `font-sans`/`font-mono`. Keep native CSS for font definitions, base behavior, artwork, registered custom properties and genuinely complex ramp motion—not a second ordinary styling system. Preserve inclusive breakpoints with `[@media(max-width:650px)]:` (and corresponding widths), not exclusive `max-[650px]:` variants. Compare rendered styles when translating old selectors: their specificity may have overridden seemingly active declarations.

## Artwork pipeline

`src/scripts/app.js` connects the home theme to `src/scripts/hero-art.js`:

1. Load `/assets/balcony.png` from `public/assets/`; never composite the old skyline.
2. Cover-crop with safe overscan for motion; use a leftward phone focus to preserve the planted facade and balcony.
3. Apply luminance/contrast and a screen-fixed ordered threshold pattern, colouring each pixel with the active canvas/accent inks. Light mode reverses coverage for bright sky and dark silhouettes.
4. WebGL moves the sampled image beneath the raster, with bounded drift/parallax and a fading pointer ripple. Do not add random threshold noise, flashing, glyphs or a reveal mask. Reuse GPU resources; cap logical resolution.
5. Suspend motion when reduced, offscreen or hidden; retain static theme updates. Mouse/pen alone drive pointer effects. A lost/unavailable WebGL context switches to real static Canvas2D Bayer fine dithering.

`src/scripts/hero-settings.js` owns the fixed Bayer fine matrix and rendering settings: 1.5px cells, 0.25 spread, 0.54 threshold, 1.1 contrast, 1 drift and 0.65 cursor strength. Ripple is the sole pointer effect. There are no hero controls, mutable tuning state, subscriptions or PNG-capture API; do not restore them without a request. Theme selection remains independent. If live rendering fails, retain the baked Tide Dark `public/assets/balcony-dither.png` poster. No-script uses that poster too.

`art-source/generate_landscape.py` remains the optional historical generator (NumPy/Pillow); the original PNG is archived in `art-source/landscape-original.png`. The editable balcony SVG and previews remain separate from the active AI-generated raster. Neither optional artwork builder is part of Astro builds. See `art-source/README.md`.
